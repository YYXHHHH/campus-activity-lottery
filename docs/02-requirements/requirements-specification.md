## 1. 项目概述
### 1.1 背景
校园活动（讲座、工作坊、体育场馆预约等）名额有限，报名人数常常远超名额。需要一套系统完成「发布 → 报名 → 抽签 → 候补递补 → 扫码签到 → 统计导出」的闭环，保证抽签随机、公平、可追溯。
### 1.2 目标
- 组织者 3 分钟内完成一个活动发布；
- 学生报名过程 ≤ 2 次点击；
- 报名截止后自动抽签，结果随机且不重复；
- 中签者退出时，候补自动递补，无需人工干预；
- 现场扫码签到，组织者实时看到签到率；
- 一键导出报名表 / 中签表 Excel。
### 1.3 MVP 范围界定
| 纳入 MVP | 暂不纳入（后续迭代） |
|---|---|
| 三角色注册登录（JWT） | 微信/统一身份认证 SSO |
| 活动 CRUD 与发布 | 活动封面图上传 |
| 报名 / 取消 / 候补意愿 | 消息通知（短信/邮件/站内信） |
| 自动抽签 + 幂等 | 分组抽签、多轮抽签 |
| 候补自动递补 | 组织者手动调整中签名单 |
| 二维码签到 | 人脸/定位签到 |
| 统计 + Excel 导出 | 图表可视化大屏 |
| SQLite 存储 | MySQL 主从、Redis 缓存 |

## 2. 术语与角色
### 2.1 术语
| 术语 | 含义 |
|---|---|
| 活动（Activity） | 一次可报名的校园活动，含名额、截止时间 |
| 报名（Registration） | 学生与活动之间的一条记录，含状态 |
| 抽签（Lottery） | 报名截止后，在全部有效报名中随机排序，取前 N 名为中签 |
| 中签（WON） | 获得参与资格，可生成签到二维码 |
| 候补（WAITING） | 未中签但接受候补，按抽签随机顺序排队 |
| 递补（Promotion） | 中签者退出后，候补队列首位自动升为中签 |
| 签到码（qr_token） | 中签后生成的不可预测随机串，编码进二维码 |
| 签到率 | 已签到人数 / 中签人数 |
### 2.2 角色
| 角色 | 说明 | 获取方式 |
|---|---|---|
| 学生 STUDENT | 浏览活动、报名、取消、查看自己的中签与二维码 | 自助注册 |
| 组织者 ORGANIZER | 发布/管理自己创建的活动、触发抽签、查看名单、扫码签到、导出 | 自助注册（MVP 阶段开放，可配置为需审批） |
| 管理员 ADMIN | 拥有组织者全部权限，且可管理所有活动与所有用户 | 由 `seed.py` 初始化，不开放自助注册 |

## 3. 功能需求
### 3.1 用户与认证（FR-1）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 学生/组织者可用「用户名 + 密码 + 姓名 + 角色」注册；用户名唯一，作为学号/工号 | P0 |
| FR-1.2 | 注册时可选角色 STUDENT 或 ORGANIZER，不允许注册 ADMIN | P0 |
| FR-1.3 | 密码使用 bcrypt 哈希存储，任何接口不得返回密码哈希 | P0 |
| FR-1.4 | 登录成功返回 JWT（有效期 24h），后续请求携带 `Authorization: Bearer <token>` | P0 |
| FR-1.5 | 提供 `GET /api/auth/me` 返回当前用户信息与角色 | P0 |
| FR-1.6 | 用户名或密码错误统一返回 401「用户名或密码错误」，不区分提示 | P1 |
| FR-1.7 | 管理员可禁用用户（`is_active=0`），被禁用用户无法登录 | P1 |
**校验规则**：用户名 4–50 位（字母/数字/下划线）；密码 ≥ 6 位；姓名 1–50 位。
### 3.2 活动管理（FR-2）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 组织者可创建活动，必填字段：名称、地点、开始时间、**报名截止时间**、**名额**；选填：描述、结束时间 | P0 |
| FR-2.2 | 校验：名额 ≥ 1；报名截止时间 > 当前时间；截止时间 ≤ 开始时间 | P0 |
| FR-2.3 | 活动状态：`DRAFT`（草稿）/ `PUBLISHED`（报名中）/ `LOTTERY_DONE`（已抽签）/ `CANCELLED`（已取消） | P0 |
| FR-2.4 | 组织者可编辑自己创建的活动，仅 `DRAFT`/`PUBLISHED` 且**尚未截止**时可改；改小名额时若已报名人数 > 新名额，返回 400 | P0 |
| FR-2.5 | 学生端活动列表仅展示 `PUBLISHED` 与 `LOTTERY_DONE` 状态的活动，支持按关键词、状态筛选与分页 | P0 |
| FR-2.6 | 活动详情返回：活动信息 + 当前用户报名状态 + 当前报名人数（可选） | P0 |
| FR-2.7 | 组织者可取消活动（`CANCELLED`），取消后不可报名，已有报名保留但不可签到 | P1 |
| FR-2.8 | 组织者只能操作 `organizer_id = 自己` 的活动；ADMIN 不受此限制 | P0 |
### 3.3 报名（FR-3）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 学生可对 `PUBLISHED` 且未过截止时间的活动报名，报名时选择「是否接受候补」`accept_waitlist`（默认 true） | P0 |
| FR-3.2 | 同一学生对同一活动只能有一条有效报名；重复报名返回 409 | P0 |
| FR-3.3 | 报名截止后或活动非 `PUBLISHED` 时，报名返回 400「报名已截止」 | P0 |
| FR-3.4 | 截止前可取消报名（`CANCELLED`），取消后可重新报名（复用原记录，状态回 `PENDING`） | P0 |
| FR-3.5 | 学生可在「我的报名」中看到全部报名及状态、中签序号、签到状态 | P0 |
| FR-3.6 | 抽签后中签者可主动退出（`WITHDRAWN`），退出后其二维码立即失效 | P0 |
| FR-3.7 | 抽签后候补者也可取消（从候补队列移除） | P1 |
| FR-3.8 | 组织者不可报名自己创建的活动（返回 403） | P1 |
### 3.4 抽签（FR-4）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 报名截止后**自动**触发抽签（定时任务，见 §9.4） | P0 |
| FR-4.2 | 也支持组织者/管理员手动触发 `POST /api/activities/{id}/lottery` | P0 |
| FR-4.3 | 抽签必须**幂等**：同一活动重复触发只生效一次，不改变已产生的名单 | P0 |
| FR-4.4 | 若有效报名人数 ≤ 名额，全部直接中签，不产生候补 | P0 |
| FR-4.5 | 若报名人数 > 名额，随机打乱后取前 `quota` 名为 `WON`；其余按 `accept_waitlist` 分为 `WAITING`（候补队列，按随机顺序）或 `LOST` | P0 |
| FR-4.6 | 抽签结果随机且不重复：每人一个唯一 `lottery_rank` | P0 |
| FR-4.7 | 记录 `lottery_seed`（随机种子）与 `lottery_at`，便于事后审计复现 | P1 |
| FR-4.8 | 每个中签者生成唯一 `qr_token`（`secrets.token_urlsafe(16)`），不可预测 | P0 |
| FR-4.9 | 未到截止时间手动触发抽签返回 400 | P0 |
### 3.5 候补递补（FR-5）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | 中签者退出（`WITHDRAWN`）后，立即从候补队列头部递补 1 人 | P0 |
| FR-5.2 | 递补顺序 = 抽签时的 `lottery_rank` 升序，保证与抽签同源的随机公平 | P0 |
| FR-5.3 | 递补者状态变为 `WON`，同时生成新的 `qr_token` | P0 |
| FR-5.4 | 递补必须与退出操作在同一数据库事务中完成 | P0 |
| FR-5.5 | 候补队列为空时，名额空缺，不做任何处理 | P0 |
| FR-5.6 | 组织者调大名额时同样触发递补（一次性补足差额） | P1 |
| FR-5.7 | 递补发生后，被递补者可在「我的报名」看到状态变为中签并可取二维码 | P0 |
### 3.6 签到（FR-6）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-6.1 | 中签学生在「我的报名」中可获取签到二维码（PNG 图片接口） | P0 |
| FR-6.2 | 二维码内容 = `{PUBLIC_BASE_URL}/checkin.html?code=<qr_token>`（手机相机扫码可直接打开；同时支持纯码解析） | P0 |
| FR-6.3 | 组织者在签到页输入/粘贴/扫码得到 code，提交 `POST /api/activities/{id}/checkin` | P0 |
| FR-6.4 | 签到校验：code 存在 → 属于该活动 → 报名状态为 `WON` → 未重复签到 | P0 |
| FR-6.5 | 重复签到返回 409，并返回首次签到时间 | P0 |
| FR-6.6 | 组织者可查看该活动的签到名单（已签到 / 未签到） | P0 |
| FR-6.7 | 支持组织者手动按学号补签（`method=MANUAL`，仅 ADMIN 或活动组织者） | P1 |
| FR-6.8 | 签到页实时展示「已签到 X / 中签 Y（签到率 Z%）」 | P0 |
### 3.7 统计与导出（FR-7）
| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-7.1 | 活动统计接口返回：报名人数、中签人数、候补人数、未中签人数、退出人数、签到人数 | P0 |
| FR-7.2 | 指标计算：中签率 = 中签人数 / 报名人数；签到率 = 签到人数 / 中签人数；名额使用率 = 中签人数 / 名额 | P0 |
| FR-7.3 | 导出「报名表 Excel」：全部报名记录 + 状态 + 签到情况 | P0 |
| FR-7.4 | 导出「中签表 Excel」：仅中签者 + 签到码 + 签到状态 | P0 |
| FR-7.5 | 文件名含活动名与日期，如 `活动名_报名表_20250101.xlsx`；表头加粗、列宽自适应、冻结首行 | P1 |
| FR-7.6 | 导出仅限该活动组织者与 ADMIN | P0 |

## 5. 业务规则与状态机
### 5.1 活动状态机
```
DRAFT ──publish──> PUBLISHED ──(截止时间到 + 抽签)──> LOTTERY_DONE
│                    │                                   │
└──────cancel────────┴──────────cancel───────────────────┘
▼
CANCELLED
```
- `PUBLISHED → LOTTERY_DONE` 由定时任务或手动触发，且必须满足 `now >= signup_deadline`。
- 转换使用**条件更新**保证幂等：
```sql
UPDATE activities SET status='LOTTERY_DONE', lottery_seed=?, lottery_at=?
WHERE id=? AND status='PUBLISHED';
-- rowcount == 0 → 已被其它线程/进程处理，直接返回
```
### 5.2 报名状态机
```
┌──(抽中)──────────────> WON ──退出──> WITHDRAWN
│                         ▲                │
PENDING ──抽签────────┼──(未中+接受候补)──> WAITING ──递补───────┘
│                  └──(未中+不接受候补)──> LOST
│
└──截止前取消──> CANCELLED ──重新报名──> PENDING
```
| 状态 | 含义 | 可签到 |
|---|---|---|
| PENDING | 已报名，等待截止抽签 | ❌ |
| WON | 中签 | ✅ |
| WAITING | 候补队列中 | ❌（递补后变 WON 才可） |
| LOST | 未中签且不接受候补 | ❌ |
| CANCELLED | 截止前取消 | ❌ |
| WITHDRAWN | 中签后退出 | ❌ |
### 5.3 关键约束（数据库层保障）
- `users.username` UNIQUE
- `registrations (activity_id, user_id)` UNIQUE
- `registrations.qr_token` UNIQUE（允许 NULL）
- `checkins.registration_id` UNIQUE（防重复签到）
- `registrations.lottery_rank` 在同一活动内唯一（应用层保证）

## 6. 非功能需求
| 类别 | 要求 |
|---|---|
| 性能 | 单活动 1000 人报名时，抽签 < 1s；列表接口 P95 < 300ms |
| 并发 | 100 并发报名不产生重复记录（依赖唯一约束 + 事务）；抽签并发触发只生效一次 |
| 安全 | 密码 bcrypt；JWT HS256；`qr_token` 使用 `secrets` 生成；所有资源接口做归属校验；SQL 全部参数化 |
| 一致性 | 抽签、退出+递补、签到均在事务内完成 |
| 可维护性 | 分层：router → service → model；业务逻辑集中在 `services/` |
| 可移植性 | 通过 SQLAlchemy + `DATABASE_URL` 切换 SQLite / MySQL，代码零改动 |
| 可部署性 | Windows 上 `python -m venv` + `pip install -r requirements.txt` + `run.bat` 一键启动 |
| 兼容性 | Python 3.11；浏览器 Chrome/Edge 最新版 |
| 日志 | 抽签、递补、签到、导出写 INFO 日志，含 activity_id / user_id |
| 数据留存 | 活动结束后数据保留，不自动删除 |

### 15.2 错误码约定
| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 40001 | 400 | 参数错误 / 报名已截止 / 状态不允许 |
| 40101 | 401 | 未登录或 token 失效 |
| 40102 | 401 | 用户名或密码错误 |
| 40301 | 403 | 无权限访问该资源 |
| 40401 | 404 | 资源不存在 / 签到码无效 |
| 40901 | 409 | 重复报名 / 重复签到 / 用户名已存在 |
