## 1. 项目概述

校园活动（讲座、工作坊、体育场馆预约等）名额有限，报名人数常常远超名额。本项目实现一套系统，完成「发布 → 报名 → 抽签 → 候补递补 → 扫码签到 → 统计导出」的闭环，保证抽签随机、公平、可追溯。

- 项目名：校园活动报名抽签与签到系统（MVP v1.0）
- 文档基线：《需求与设计文档》v1.0、《开发文档》v1.0

## 2. 项目目标与范围

**目标（摘要）**

- 组织者 3 分钟内完成一个活动发布；
- 学生报名过程 ≤ 2 次点击；
- 报名截止后自动抽签，结果随机且不重复；
- 中签者退出时，候补自动递补，无需人工干预；
- 现场扫码签到，组织者实时看到签到率；
- 一键导出报名表 / 中签表 Excel。

**MVP 范围界定**

| 纳入 MVP | 暂不纳入（后续迭代） |
| --- | --- |
| 三角色注册登录（JWT） | 微信/统一身份认证 SSO |
| 活动 CRUD 与发布 | 活动封面图上传 |
| 报名 / 取消 / 候补意愿 | 消息通知（短信/邮件/站内信） |
| 自动抽签 + 幂等 | 分组抽签、多轮抽签 |
| 候补自动递补 | 组织者手动调整中签名单 |
| 二维码签到 | 人脸/定位签到 |
| 统计 + Excel 导出 | 图表可视化大屏 |
| SQLite 存储 | MySQL 主从、Redis 缓存 |

## 7. 风险与应对

| # | 风险 | 影响 | 概率 | 应对（落实点） |
| --- | --- | --- | --- | --- |
| R1 | SQLite 并发写锁 `database is locked` | 报名高峰 500 | 高 | WAL + timeout=30 + 重试装饰器；压测 100 并发；终极方案切 MySQL |
| R2 | `uvicorn --reload` / 多 worker 导致调度器多实例 | 重复抽签、名单错乱 | 中 | 部署规范锁死单 worker；run.bat 演示/开发模式分离；条件 UPDATE 兜底 |
| R3 | naive datetime 混入 | 截止判断错 8 小时 | 中 | 全项目唯一入口 `utcnow()`；code review 专项检查 |
| R4 | 二维码截图转发代签 | 冒名签到 | 中 | 签到页显示姓名/学号人工核对；迭代方向 30s 轮换动态码 |
| R5 | bcrypt 版本兼容 | 启动告警/哈希失配 | 低 | passlib 1.7.4 + bcrypt 4.1.3 双 pin，禁止单独升级 |
| R6 | 导出中文文件名乱码 | 文件名不可读 | 中 | `filename*=UTF-8''` 编码；中文名用例覆盖 |
| R7 | MySQL 迁移差异 | 切库后约束丢失 | 中 | DDL 注释标注；迁移跑全量 pytest；quota 应用层校验 |
| R8 | 单活动大数据量导出内存 | OOM（极端） | 低 | 分批 append；MVP 千行级无风险 |
| R9 | SECRET_KEY 泄露/示例值 | token 可伪造 | 中 | 启动强校验；README 注明生成方式 |
| R10 | 调度任务异常静默 | 到期不抽签 | 低 | 兜底 I-2 + 日志 + stats 可观测 |
| R11 | 组织者误改截止到过去 | 学生端突然截止 | 低 | 前端二次确认；详情页提示自动抽签 |
| R12 | 换机部署失败 | 验收失败 | 中 | run.bat 固化流程；README 常见问题；A12 换机演练 |

> 《需求与设计文档》§14 另列 8 项风险，与本表一致（SQLite 并发写锁、定时/手动抽签并发、多 worker、二维码代签、截止时间边界、时区、换机部署、名额调小超员）。

## 8. 质量与配置管理

- **自动化测试**：pytest + TestClient + 内存 SQLite，覆盖全部 P0 需求（映射见《测试计划》附录 D）；合并前必须全绿。
- **依赖锁定**：`requirements.txt` 固定版本；passlib 与 bcrypt 双 pin。
- **配置管理**：`.env` 不入库（含 SECRET_KEY）；`app.db`、`app.log`、`.pytest_cache`、`__pycache__` 由 `.gitignore` 排除。
- **部署红线**：单进程单 worker，演示/验收禁用 `--reload`；条件 UPDATE 作为抽签幂等的最后防线。
- **基线管理**：每个里程碑保持可启动、可演示、可回滚。
