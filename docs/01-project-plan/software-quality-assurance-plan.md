# 校园活动报名抽签与签到系统 —— 软件质量保证计划（SQAP）

> **所属阶段**：项目计划（质量）　|　**版本**：v1.0　|　**整理日期**：2026-10-02
> **内容来源**：《需求与设计文档》§6 非功能需求；《开发文档》§7 边界与异常、§9 里程碑、§10 测试与验收；《测试计划》《测试报告》《验收报告》。

## 1. 目的与范围

规定本项目在需求、设计、编码、测试、部署、验收各阶段应达到的质量目标、采取的质量活动与记录方式，适用于本系统 MVP v1.0 的全部交付物。

## 2. 质量目标与度量

| 质量属性 | 目标 | 度量方式 | 结果 |
| --- | --- | --- | --- |
| 功能完整性 | P0 需求 100% 实现并有测试覆盖 | 需求↔模块↔测试映射表 | 达成 |
| 性能 | 1000 条报名抽签 < 1s | 计时打点 | 48ms |
| 并发正确性 | 100 并发报名无重复记录 | 唯一约束 + 并发脚本 | 0 重复 |
| 可靠性 | 抽签幂等可复现；签到防重复 | 条件 UPDATE + 唯一约束 | 通过 |
| 安全性 | 密码 bcrypt、JWT HS256、SQL 参数化、资源归属校验 | 代码走查 + 用例 | 通过 |
| 可维护性 | 严格三层 routers→services→models | 依赖方向检查 | 通过 |
| 可移植性 | 仅改 DATABASE_URL 切换 MySQL | 配置检查 | 通过 |
| 文档完整性 | 全生命周期文档齐备 | 文档总索引 | 15 篇 |

## 3. 组织与职责

| 角色 | 质量职责 |
| --- | --- |
| 需求/产品 | 需求可验证、验收标准明确 |
| 开发 | 遵守设计规范与编码红线，自测通过 |
| 测试 | 设计用例、执行自动化与手工验收 |

## 4. 质量依据

- 《需求规格说明书》——验收标准（附录 A）与非功能需求；
- 《开发文档》§6 依赖红线、§7 异常体系与日志规范、附录 B 错误码总表；
- 《部署运行手册》——部署红线（单进程单 worker，演示禁用 --reload）；
- 依赖版本锁定：requirements.txt 固定版本，passlib 与 bcrypt 双 pin 禁止单独升级。

## 5. 过程质量控制

| 阶段 | 质量活动 | 准出条件 |
| --- | --- | --- |
| 需求 | 需求评审、验收标准确认 | FR 编号齐全、P0/P1 明确 |
| 设计 | 设计评审（架构/接口/数据） | 接口契约与错误码确定 |
| 编码 | 代码走查（时间入口、事务边界、依赖方向、错误码） | 三层依赖无反向、异常体系统一 |
| 测试 | 自动化测试 + 手工验收 | pytest 全绿、A1~A12 通过 |
| 交付 | 文档齐备、可换机运行 | 文档索引完整、run.bat 可用 |

> 里程碑纪律：每个里程碑结束时保持「可启动、可演示、pytest 全绿」；P0 需求未覆盖测试不得合并。

## 6. 评审与验证活动

- 需求评审：对照用户验收标准评审《需求规格说明书》；
- 设计评审：评审概要/详细设计、接口设计与数据库设计；
- 代码走查：重点核查 UTC 时间入口、事务提交边界、依赖方向、错误码统一；
- 测试验证：见《测试计划》与《测试报告》；
- 验收：见《验收报告》（A1~A12 与性能并发）。

## 7. 缺陷管理

- 分级：阻断 / 严重 / 一般 / 建议；
- 记录与闭环：开发期缺陷 11 项、验收期缺陷 8 项，全部修复并回归，记录见《测试报告》§6 与《验收报告》§1；
- 未复现报告项与建议项单独记录，不阻断验收。
